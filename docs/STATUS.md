# Implementation status

This repository is a **development alpha**. The complete agreed performance-platform plan is not finished. The implemented paths below are real code rather than simulated UI, but the platform has not passed the 32-player performance acceptance run or physical iPad/audio-interface validation.

## Implemented

- Monitor workspace with a left statistics/browser-audio sidebar and two full-height meter rows for input and output nodes. Each node has one vertical sample-peak bar, green/yellow/red with explicit clipping and stale states. Peak collection covers every sample between telemetry updates and includes native output channel summing. Server-process CPU and current resident memory are sampled off the audio thread. Browser monitoring stays connected across tabs and stage navigation. The saved revision/status appears beneath the project name; the redundant upper-right Ensemble button is removed.

- Saved graph revision history is separate from the live edit counter. Edits update the recoverable working copy and engine immediately; a server timer saves one history snapshot per dirty minute, and Cmd/Ctrl+S or Save revision saves immediately after queued live edits. Clean saves are idempotent, old history is retained, and the header shows saved revision/dirty state. Pending deadlines survive server restarts.

- Native input/output channel routing tables with per-signal physical channel selection or None, repeated input sources, summed output destinations, 1:1/disconnect presets, and a stereo mixdown preset with gain adjustment. Native device frames support physical channels 1–64 while graph signals remain 1–8 channels. Device discovery reports the selected-rate channel count; legacy sequential/offset routing is preserved. Routes persist through the working copy, saved revisions and undo. Physical interface verification and load/endurance testing of the larger native buffers remain pending.

Native input startup now follows audio-engine startup and shutdown; the separate capture button/API command is removed. Selected-input startup failures are surfaced before accepting engine activation, and no selected inputs is valid. The workspace Rust suite plus the empty/unchecked-input regression, frontend build/unit tests, and Chromium integration suite were run for this change. Physical input startup and capture remain manual checks.

- Subgraph library beneath the node library, with private entries, permanently public entries, immutable version selection, owner-only new-version saves, and independent forks. Inserted graphs embed their chosen snapshot and bundled WAV samples with fresh project IDs. Library updates never rewrite existing projects. Earlier private drafts remain private when a later version is published.
- Drag/drop from both libraries controls initial placement. Box selection and Control/Command-click select multiple nodes; group movement saves all positions together, and deletion handles selected subtrees. Right/middle dragging pans.

- Nested subgraphs with breadcrumb navigation and named audio/control/spectral boundary nodes. Parent ports follow boundary labels, widths and FFT formats. Compilation validates and flattens the hierarchy; nesting has no separate depth limit, within the existing 256-node/2,048-edge project budget. Duplicate in the context menu or `D` copies stored settings and complete internal subgraphs using new IDs; external cables are not copied. Subtree deletion and undo work during playback.
- Global clock `tempo` control input changes engine BPM at sample time without resetting phase. One tempo driver is allowed per project; connected transport tempo is read-only. Disconnect retains the current engine tempo for this activation.
- Native input device listing, system enablement and per-node routing, plus disabled/unavailable/capture-off feedback. Browser nodes and monitor setup list browser-exposed microphones, retain device selections locally, request permission explicitly, and report denied/blocked/unavailable access. Native multidevice and real microphone permission/capture behavior still require physical-device testing.

- Live graph editing in all modes, node Edit/Delete context menus, selection deletion with Backspace/Delete, and Ctrl/Cmd+Z graph undo. Space and the Play button activate an inactive show and play, then toggle pause/resume. Text entry/dialog controls retain normal keyboard behavior.
- Sample-rate `audio_to_control` with scale/offset for FM; connected oscillator Frequency follows each sample while manual edits stay smoothed. No through-zero FM or oversampling.
- Spectral magnitude/phase multiply/add and separate 33-point drawn magnitude/phase curves, editable in the modal during playback. Curves are persisted configuration; negative bins mirror positive bins, with DC/Nyquist phase retained. Crossfades, physical timing, and heavy live-edit/spectral load remain unverified.

- `init.sh --update` rebuilds the frontend and builds the release server with locked dependencies, reusing up-to-date Cargo artifacts, without interactive setup or startup-service changes. It requires installed build tools; source updates and server restarts remain separate.

- Three transparent visualizer nodes: numeric/string control, multichannel audio spectrogram, and spectral spectrogram plus complete positive-bin magnitude/phase graphs. Analysis/history advances once per DSP block; browser presentation is 20 Hz. History is bounded to 128 columns × 32 bands per channel; graphs allow at most 16 visualizers. No visualization history enters persistence/undo. Visualizer resource use is not covered by the prior load baselines.
- A typed numeric/UTF-8 control-value contract for visualizer chains, with fixed-capacity 256-byte runtime strings, modal-only disconnected input literals, and server rejection of text into numeric-only processors. General string operators and external text-event input remain pending.

- Header gear menu for project settings, system settings, and an autoscrolling project engine console with a standalone tab. Server history is bounded and in-memory; it is not a complete process stdout/stderr archive.
- Original-preserving WAV caches at the global sample rate, prepared on upload, current-project settings changes, and lazy loading of other projects. Conversion/loading/setup share an indeterminate progress modal. WebRTC rate adapters preserve phase across packets at non-48-kHz engine rates.
- Manual output latency entries and relative interface delay correction, plus an engine-sample metronome with a browser visual reference and a 60-second stop. Hardware loopback calibration, browser/network latency compensation, and drift correction remain unverified/incomplete.
- Hover/focus waveform snapshots on audio connections: 256 actual source samples per channel, bounded on-demand capture, no project persistence. This is a rough visual preview, not a calibrated oscilloscope.
- Oscillator modal selects sine, triangle, sawtooth, square, or noise; sine remains the default. Sawtooth/square edge correction reduces aliasing. A native output queue bug that inserted periodic silence when driver callbacks exceeded the DSP queue target has been reproduced in simulation and corrected; physical listening confirmation remains pending.

- Server binding defaults to `0.0.0.0:4000` (all IPv4 interfaces), including newly generated startup scripts; `PR0_BIND` can override it. `--start --host HOST --port PORT` supplies component overrides via `PR0_HOST`/`PR0_PORT`, including with existing saved launch scripts. Either flag can be used alone; TLS/data settings are retained.
- Vite/Vue/TypeScript application, locally bundled fonts, responsive graph workspace, custom stage-instrument node style, compact math blocks, typed animated cables, and touch/keyboard interactions.
- Native dialog parameter editor, immediate unconnected edits, connected read-only engine values, source navigation, five-second traces, stale status, and undo. Channel width and WAV upload controls are available in relevant node modals.
- Shared engine ownership status broadcasts on activation/deactivation and accompanies reconnect snapshots. Browsers discard older status snapshots, clear inactive telemetry, and disconnect browser audio when a remote conductor deactivates the show. Status reports accepted orchestration commands, not physical device completion.
- Reconnecting WebSocket clients receive a current project snapshot, including edits made while offline; queue overflow also reloads the snapshot. Recovery preserves the stage view and part selection. Retired socket callbacks are ignored.
- Rust workspace, SQLite persistence and revision snapshots, local accounts, Argon2 passwords, invitation-only registration after bootstrap, expiring sessions, project membership, role checks, and single-use invitations.
- Performer stage view with read-only notation/piano roll, part selection, shared bar/beat and tempo, role-aware launch/stop cues, fullscreen access, and a timing-loss warning that holds the score. Browser monitoring persists across workspace/stage navigation and disconnects on show deactivation. Physical device timing is not validated.
- Project settings dialog edits the name, performance mode, and initial tempo during preparation. Remote activation disables edits; newer project revisions require reopening the dialog. Saved settings refresh the project picker.
- Project creation with structured/conducted/freeform modes; shared transport and beat-preserving next-beat tempo updates; mode-aware part startup, next-beat part launch/stop, and per-part playback telemetry/UI.
- Part preparation controls persist names, loop lengths, and default notation/piano-roll display. Switching parts restores each default; performance mode uses it without showing editing controls. Notes outside shortened loops remain stored and produce a playback-boundary warning.
- Score-driven polyphonic synth, basic notation rendering and piano-roll note editing, treble/bass/alto/tenor clefs, optional major key signatures, meter numerator/denominator editing and signature visibility, part/performer routing, JSON project import/export, and basic MusicXML import/export with warnings.
- Internal synth note ownership isolates overlapping notes and parts sharing an instrument. Part stop/relaunch releases only held notes, and transport Stop resets scheduling at beat zero. Pause/resume restores held notes to their original release times; stopping a paused part clears suspended notes. Internal voice phase/envelopes restart on resume. External MIDI/OSC merges shared pitches until their last release; OSC panic sends note-offs.
- Validated acyclic audio/control/spectral graphs, 1–8 channels, one driver per inlet, finite numeric ranges, prepared buffers, and bounded queues.
- Math/conversion/logic nodes; global/local metronomes, phase-preserving clock ratios, counters, gate, random, LFO, trigger, change/select, sample-and-hold, ramp, and a sample-counted ADSR control envelope with retriggering; a 1–16-step control sequencer with value, index, and pulse outputs.
- Native/browser input nodes, output, channel mapping, mono splitting and merging for 1–8-channel bundles, gain/mixer/meter, oscillator/noise/polyphonic synth, pan/crossfade/audio gate, delay/reverb/envelope follower, compressor/expander/limiter/noise gate.
- Third-/fifth-order Butterworth low/high-pass filters, band-pass/notch, three-/five-band parametric EQ, and a 16-band carrier/modulator vocoder.
- Streaming FFT/real FFT, inverse transforms, magnitude/phase conversion, and spectral gain; preallocated framing and overlap-add. Parallel feed-forward audio paths receive compensation for FFT branch latency.
- WAV sample upload (up to 30 seconds, 1–8 channels), sample playback, and sample phase-vocoder preparation with independent time/pitch controls. Phase-vocoder settings are structural and prepared off-thread before playback.
- Persistent System audio settings select 44.1/48/88.2/96 kHz, 32–1024-frame DSP scheduling blocks, and checked CPAL output interfaces. Audio output node modals select an enabled interface. Bounded callback queues remain f32; the driver chooses its callback buffer. Engine enablement moves to the footer and show activation waits for selected-output startup. Native inputs are selected in System settings, routed individually in node modals, and captured automatically when the audio engine starts. Physical devices and independent-clock drift are not validated.

Cancellation marks pending offers; final registration rejects cancelled offers or inactive shows. Cleanup releases failed negotiations and cannot remove a newer session’s reservation.
- Browser audio setup isolates each connection attempt, stops late microphone tracks after cancellation, cancels ICE waits, and ignores callbacks/statistics from retired peers. In-flight offers finish before remote cleanup and replacement; an unresponsive offer can still delay reconnect. Playback-resume failures are handled in the UI.
- WebRTC/Opus master stereo monitor, selectable dedicated monitor outputs, and browser microphone uplinks. A real local Chromium connection is included in the browser test. Diagnostics expose jitter, packet loss, round-trip time, and average jitter-buffer duration.
- MIDI output discovery, score note delivery to named CoreMIDI ports with per-part channels, OSC UDP score note delivery with editable addresses, and an external worker isolated from device callbacks.
- Native HTTPS serving and a documented local CA workflow.

Replacing an existing service requires confirmation before regenerating its launch script.
- Plugin trait example, built-in registration documentation, developer instructions, and source-plugin examples inside the DSP crate.

## Incomplete features from the agreed plan

1. **Realtime execution and validation:** rendering currently uses an orchestration worker feeding lock-free device queues, not DSP directly in a high-priority callback. Hardware sample-clock/timestamp mapping, scheduling budgets, graceful overload handling, input drift correction, graph resource estimates, and a 60-minute 32-player load test remain required.
2. **Personal monitoring:** browsers can select the master mix or one of up to 32 dedicated patch monitor outputs. Automatic per-performer sends, mix-minus construction, and monitor assignments remain pending. Microphone loss concealment, adaptive input buffering, per-performer latency calibration, and authoritative monitor-age reporting remain pending. Use headphones; there is no implemented automatic feedback suppression.
3. **Performance modes:** modes and launch permissions exist, but conducted cue distribution, snippets, performer-owned effect controls, transport authority delegation, count-in/lookahead, and published performance snapshots need completion. Structured parts begin together; conducted/freeform parts wait for a launch. Commands during playback take effect at the next integer engine beat; commands while stopped or paused apply immediately. Stop resets independent modes to idle.
4. **Live graph editing:** the UI and API support adding/moving/deleting nodes, wiring, structural modal edits, and undo in all active show modes. Prepared replacements install between DSP blocks without waiting for a bar. Structured score/settings changes and all mode changes remain inactive-only; deleting an instrument clears its route. Unchanged parts retain playback position, cues, suspended notes, and synth voice phase/envelopes across replacement. New or musically changed conducted/freeform parts start idle. Unchanged nodes also retain effect/control runtime storage when configuration, input contracts, and latency compensation match. Crossfades, state continuity for edited effect configurations and scores/routes, pending-revision controls, and graph-level delayed feedback are unfinished.
5. **Composition:** basic notes work, but robust multi-voice engraving, chords/rest layout, ties/tuplets editing, mid-score key/meter changes, dynamics, collision handling at dense onsets, and the broader MusicXML subset remain incomplete. Noteheads and the playhead now share a quarter-beat scale with optional viewport following; rendered SVG alignment is tested for uneven onsets. Duration glyphs now support whole through 64th notes, single/double dots, and tied decompositions on a 1/16-quarter-beat grid up to 256 beats. Unsupported custom/tuplet durations are marked with their exact quarter-beat value and a warning; their placeholder glyph is not a duration claim. Decompositions do not yet enforce measure boundaries or resolve polyphonic collisions. Device/network timing has not established a validated performance score follower.
6. **Control library:** full typed message payloads, ordered fan-out, pack/unpack, routing, bounded event delays, and Pd-compatible trigger/value semantics are not all implemented. Current numeric control nodes evaluate at sample rate.
7. **Remaining audio library:** reusable patch inlets/outlets, standalone biquad/resonant filters, binary spectral arithmetic and additional masking operators, full block feedback, selectable vocoder band count, and latency metadata throughout the SDK are unfinished. Real FFT currently shares the complex FFT implementation, rather than an optimized half-spectrum path.
8. **Collaboration:** revision conflict detection works; fine-grained edit leases, granular operations, shared undo, membership management/revocation, and project export including sample assets need completion.
9. **Integration:** incoming OSC transport and graphical-control messages are implemented with configurable IPv4 bindings; MIDI input discovery is implemented, while MIDI input routing and generic graph mapping remain pending. Network MIDI session management and timed OSC bundles remain pending. External note delivery is best effort.
10. **SDK/contracts:** built-ins still require an explicit dispatcher branch. Automatic Rust-to-TypeScript generation, declarative plugin registration, full typed parameter metadata, sandboxing, and dynamic loading are not present.
11. **UI telemetry:** no server-side per-modal subscription filtering, min/max audio-rate summaries, robust clock drift regression, per-edge event pulses, or correct undo grouping across an arbitrarily long slider gesture yet.
